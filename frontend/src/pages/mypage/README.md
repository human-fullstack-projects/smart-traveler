# 마이페이지 데이터·접근·로그인 연결

이 폴더의 api / data / hooks / components / pages / tests로 기능을 분리한다. App과 AuthContext에는 라우팅·인증 상태 연결만 둔다.

## 저장·접근 기준

- 비회원은 마이페이지 홈과 내 코스만 사용할 수 있다. 예약·게시글 상세 주소로 직접 들어가도 로그인 안내를 표시한다.
- 임시 코스는 App 메모리에만 저장한다. 사이트 내 hash 이동과 가입·로그인 화면 이동은 유지하고, 새로고침·탭 종료·외부 페이지 이탈은 초기화한다.
- 기존 `smart-travel-mypage-v1` 공용 샘플은 읽거나 회원 자료로 이전하지 않는다. 기존 브라우저 저장값 자체를 임의로 삭제하지도 않는다.
- 로그인 후 `/api/mypage/courses/import`로 회원 연결한다. 가입 직후에는 자동 로그인하지 않으므로 로그인까지 같은 탭에서 진행한다.
- 회원 연결 실패는 원래 회원과 clientId를 유지한다. 다른 계정으로 로그인해도 그 계정으로 넘기지 않는다. 원래 계정에 로그인하고 재시도한다.
- 계정이 바뀌면 화면의 이전 자료는 즉시 가리고, 늦은 API 응답은 버린다. 서버 오류와 비로그인을 구분한다.
- 코스·예약·게시글은 별도 배열이며, 회원 자료는 서버가 로그인 소유자로 필터링한다. 다른 사람의 상세 주소는 접근 제한 화면이다.

## 직접 확인하는 순서

1. 로그아웃 상태로 `#/mypage`를 열어 로그인 안내와 내 코스 메뉴를 확인한다.
2. `#/my-courses`에서 임시 코스를 보관한다. 장소는 첫날에 입력되며 AI 생성 결과는 아니다.
3. 홈·회원가입·로그인 화면 사이를 이동해도 코스가 유지되는지 확인한다.
4. `#/reservations`, `#/my-posts`, 각 상세 경로를 직접 열어 로그인 안내를 확인한다.
5. 로그인하면 회원 코스로 연결되는지 확인한다. 이후 새로고침 시 서버에서 본인 코스를 조회한다.
6. 실패한 경우 새로고침하지 않고 '다시 불러오기·연결'로 재시도한다.
7. 로그아웃한 뒤 다른 회원으로 로그인해 이전 회원의 코스가 보이지 않는지 확인한다.
8. 비회원 임시 코스를 만든 뒤 새로고침·사이트 이탈·뒤로가기를 해 임시 코스가 사라지는지 확인한다.

## 빌드 없는 상태 테스트

frontend에서 `node src/pages/mypage/tests/verify.mjs`를 실행한다. 날짜·접근·로그인 연결·재시도·계정 분리·응답 유실·이탈 초기화를 검사한다. 이 테스트는 UI·Java·실제 DB 통합 검증을 대신하지 않는다.

새 DB 테이블과 서버 API 설명은 `smarttraveler/db/mypage/README.md`를 참고한다. 코스 사진·피드백·실제 취소/환불 및 AI 생성기 연동은 다음 구현 단계다.

## 2단계: 홈·정보·취향

- 홈: 프로필 이미지·닉네임, AI여행생성 펼침 영역, 내 정보관리·여행 스타일 관리 링크를 추가했다.
- 내 여행 코스 / 내 여행 추천 / 내 예약 명칭을 홈·마이페이지 메뉴에 적용했다.
- `/my-profile`: 아이디는 읽기 전용, 닉네임·이메일·프로필 사진은 저장한다. 비밀번호 변경을 선택하면 현재·새 비밀번호·확인을 검사한다. 저장 후 입력한 비밀번호는 화면 상태에서 비운다.
- `/my-travel-style`: 일정 강도, 기상 시간, 관심사·음식·교통·여행 스타일별 선호·기피 및 강도 1~3을 조회·수정한다. 선택을 모두 해제하는 저장도 지원한다.
- 비회원의 두 관리 화면 직접 접근은 로그인 안내로 제한한다. 서버도 현재 로그인 소유자와 expectedMemberId 일치를 검사한다.
- 프로필 사진은 PNG·JPEG·WebP 1MB 이하를 받아 브라우저에서 최대 256픽셀 PNG로 조정하고, 서버에서 실제 이미지 검증·재인코딩 후 보관한다.
- 대화로 AI여행 생성은 `/ai-course`를 열고 입력 후 기존 onStart로 대화를 시작한다. 조건선택은 `/conditions`로 이동한다. 조건검색 이후 실제 일정 생성은 여전히 연결 준비 단계다.
- 취향 저장은 기본 취향 테이블만 변경한다. 개별 여행 조건이 우선이며, 기존 예약·확정 조건·코스에는 소급 적용하지 않는다. AI 생성기가 기본 취향을 실제로 읽는 연동은 별도다.
- 빌드 없는 검증: `node src/pages/mypage/tests/settings-verify.mjs`.
