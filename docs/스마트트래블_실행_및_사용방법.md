# 스마트 트래블 실행 및 사용 방법

기준일: 2026-11-04  
대상: 현재 구현된 여행 대화·관광지 조회·관광지 후보 추천 기능

## 1. 먼저 확인할 내용

현재 프로젝트는 아래 네 가지를 함께 사용한다.

| 구분 | 역할 | 기본 주소 |
| --- | --- | --- |
| MariaDB | 대화·여행 조건·지역·관광지 저장 | `localhost:3306` |
| Python AI 서버 | LangChain·LangGraph, OpenAI 조건 추출, 관광공사 API 조회 | `http://127.0.0.1:8001` |
| Spring Boot 서버 | 화면 요청 처리, 대화·조건·관광지 저장 | `http://localhost:8080` |
| React 화면 | 대화, 조건 확인, 관광지 조회 및 추천 결과 표시 | Vite 실행 시 터미널에 표시되는 주소 |

**대화 기능을 사용하려면 MariaDB, Python 서버, Spring 서버, React 화면이 모두 필요하다.** Python 서버의 OpenAI API 키는 여행 조건 추출·추천에 사용하고, 한국관광공사 API 키는 지역·관광지 목록 조회에 사용한다. 두 키는 서로 다르다.

### 설치 준비

- Java 21, Python 3.11 이상, Node.js·npm, MariaDB
- OpenAI API 키와 OpenAI API 사용 권한
- 공공데이터포털에서 활용 신청한 **한국관광공사 국문 관광정보 서비스**의 일반 인증키(Decoding)
- 팀에서 공유한 기존 스마트 트래블 DB 스키마와 각자 사용할 DB 접속 정보

현재 프로젝트에서는 Java 21, Python 3.11 환경을 사용했다. 이 문서의 명령은 **Windows PowerShell** 기준이다. 아래의 프로젝트 경로는 현재 개발 PC의 예시이므로, 다른 PC에서는 실제 저장 위치로 바꾼다.

```text
D:\mingyu\workspace\teamwork\smart-traveler
```

## 2. DB 준비

1. MariaDB를 실행한다.
2. Spring 서버의 `smarttraveler/src/main/resources/application.properties`에서 연결 대상을 확인한다. 기본 DB 이름은 `smart_travel_db`이며, 필요하면 Spring을 실행하는 환경에서 `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`를 설정할 수 있다.
3. 해당 DB에 팀에서 공유한 **기존 전체 스키마**가 있는지 확인한다. 필요한 테이블에는 `chat_sessions`, `chat_messages`, `region`, `region_external_code`, `place`가 있다.
4. `chat_session_conditions`가 없다면 기존 스키마를 먼저 준비한 다음, `smarttraveler/db/chat_session_conditions.sql`을 DB 도구에서 해당 DB에 실행한다. 이 SQL은 여행 조건 테이블 하나를 만들며 **전체 스키마를 대신하지 않는다.**

기존 서버 설정에는 Hibernate 스키마 자동 갱신이 켜져 있다. 실행하거나 테스트하기 전에 **어느 DB에 접속하는지 확인**한다. DB 비밀번호는 Git이나 공유 문서에 적지 않는다.

## 3. 처음 한 번만: Python 라이브러리 설치

PowerShell을 열어 아래 명령을 실행한다.

```powershell
cd D:\mingyu\workspace\teamwork\smart-traveler\ai-server
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

이미 `ai-server/.venv`에 필요한 라이브러리가 설치되어 있다면 건너뛰어도 된다. GitHub에서 새로 받은 팀원은 각자 설치해야 한다. 가상환경 폴더는 Git에 올리지 않는다.

## 4. Python AI 서버 실행 — 첫 번째 PowerShell 창

### 4-1. 두 API 키 설정

**두 키를 Python 서버를 실행할 같은 PowerShell 창에서 설정한다.** 다음 두 줄은 그대로 입력한다. 따옴표 안의 문구는 키가 아니라 입력을 요청하는 안내 문구다.

```powershell
$env:OPENAI_API_KEY = Read-Host "OpenAI API 키를 입력하세요"
$env:TOUR_API_KEY = Read-Host "공공데이터 일반 인증키(Decoding)를 입력하세요"
```

각 줄을 실행하면 입력 안내가 나온다. **그때 해당 키를 PowerShell에 붙여넣고 Enter를 누른다.** `Read-Host`로 입력한 값은 화면에 보이므로 주변에 노출되지 않도록 주의한다. 실제 키를 이 문서, GitHub, 채팅 또는 명령문의 안내 문구 안에 붙여넣지 않는다.

이미 같은 창에서 두 키를 설정했다면 다시 입력할 필요가 없다. 다음 명령은 키 값을 표시하지 않고 설정 여부만 보여준다.

```powershell
[bool]$env:OPENAI_API_KEY
[bool]$env:TOUR_API_KEY
```

각 줄에서 `True`가 나오면 해당 창에 값이 있다는 뜻이다. **키가 유효한지나 서비스 사용 승인이 되었는지까지 확인하는 것은 아니다.** 이 방식으로 설정한 값은 PowerShell 창을 닫으면 사라진다.

### 4-2. AI 서버 시작

같은 PowerShell 창에서 실행한다.

```powershell
cd D:\mingyu\workspace\teamwork\smart-traveler\ai-server
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

실행 중인 창은 닫지 않는다. 브라우저에서 `http://127.0.0.1:8001/health`에 접속해 `{"status":"ok"}`가 보이면 **Python 서버가 실행 중이라는 의미**다. OpenAI API와 관광공사 API 호출까지 성공했다는 뜻은 아니다.

기본 OpenAI 모델은 `gpt-4o-mini`다. 실제 OpenAI 호출에는 API 사용량에 따른 비용이 발생할 수 있다.

## 5. Spring 서버 실행 — 두 번째 PowerShell 창

새 PowerShell 창을 열어 실행한다.

```powershell
cd D:\mingyu\workspace\teamwork\smart-traveler\smarttraveler
.\gradlew.bat bootRun
```

서버가 실행된 창도 닫지 않는다. 다른 DB 접속 정보가 필요하면 **이 창에서** `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`를 설정한 후 실행한다. 첫 실행에는 Gradle과 라이브러리 다운로드가 필요할 수 있다.

Spring 서버는 기본적으로 `http://127.0.0.1:8001`의 Python 서버를 호출한다. Python 서버 주소를 변경한 경우에만 Spring 실행 환경의 `AI_SERVICE_URL`을 맞춘다.

## 6. React 화면 실행 — 세 번째 PowerShell 창

새 PowerShell 창을 열어 실행한다. `npm ci`는 처음 받았거나 의존성이 변경되었을 때 실행한다.

```powershell
cd D:\mingyu\workspace\teamwork\smart-traveler\frontend
npm ci
npm run dev
```

터미널에 표시되는 `Local` 주소를 브라우저에서 연다. 화면의 `/api` 요청은 Vite 개발 설정을 통해 `http://localhost:8080`의 Spring 서버로 전달된다.

## 7. 대화와 관광지 추천 사용하기

### 7-1. 대화 시작

1. 메인 화면에 여행 계획을 입력하고 **대화 시작하기**를 누른다. 예: `친구와 부산으로 2박 3일 여행을 가고 싶어.`
2. 대화 화면에서 안내에 따라 출발 날짜, 성인·아동 인원, 동행, 교통수단 등 빠진 조건을 답한다. Enter는 전송, Shift+Enter는 줄바꿈이다.
3. 오른쪽 **여행 조건** 영역에서 추출된 값을 확인한다. **조건 직접 입력**을 눌러 수정할 수도 있다. 조건을 바꾸면 기존 확인 상태는 해제된다.

AI가 표현을 잘못 이해할 수 있으므로 지역·날짜·인원은 사용자가 확인한다. 현재 여행 기간 입력 기준은 1~7일이다.

### 7-2. 지역 선택과 관광지 가져오기

1. 대화 화면 오른쪽에서 **관광지 찾아보기**를 누른다.
2. 시도를 선택하고, 필요하면 시군구도 선택한다.
3. **관광지 가져오기**를 누르면 한국관광공사 API에서 목록을 가져온다.
4. **대화 조건에 반영**을 누르면 선택한 지역이 여행 조건에 반영된다.

관광지를 가져오면 **현재 조회한 페이지의 관광지와 지역 정보가 DB에 저장**된다. 현재 페이지는 10건 기준이며, 다음 페이지도 보고 싶으면 **다음**을 눌러 가져온다. 전국 관광지를 자동으로 전부 저장하는 기능은 아직 없다.

이미 같은 출처와 원본 ID로 저장된 관광지를 다시 가져오면 중복 생성 대신 해당 API 정보를 갱신한다. 수동으로 관리한 설명·이미지·비활성화 및 검증 상태는 유지한다. 현재 저장하는 정보는 이름, 주소, 위경도, 전화번호와 지역 등이며 상세 설명·운영시간·이미지 전체를 수집하지 않는다.

### 7-3. 조건 확인 후 관광지 추천

1. 빠진 필수 조건을 모두 입력한다.
2. 안내에 따라 `확인했어` 또는 `추천해줘`라고 답한다. `맞아요`, `그대로 해주세요` 등 일부 확인 표현도 사용할 수 있다.
3. Python AI 서버가 해당 지역에 저장된 **활성 관광지 후보 중 최대 세 곳**을 선택해 보여준다. 장소 이름과 주소는 DB에 저장된 값이다.
4. 해당 지역에 저장된 관광지가 없다는 안내가 나오면 7-2의 **관광지 찾아보기**에서 지역을 선택하고 관광지를 가져온 뒤 다시 요청한다.

현재는 저장된 장소를 이름순으로 최대 30개까지 후보로 가져온다. 장소 상세와 실시간 운영 여부는 별도로 확인해야 한다.

## 8. 새로고침과 서버 재시작

- 대화 메시지와 여행 조건은 서버 DB에 저장된다. 저장이 끝난 뒤 같은 서버 세션이 유효하면 새로고침해도 다시 불러올 수 있다.
- 현재 비회원 대화는 Spring의 서버 세션에 연결되어 있다. **Spring 서버를 재시작하거나 세션이 만료되면**, DB에 내용이 남아 있어도 현재 방식으로 이전 비회원 대화에 다시 접근할 수 없다. 이 경우 메인에서 새 대화를 시작한다.
- Python AI 서버의 코드나 환경변수를 바꿨다면 Python 서버를 재시작해야 적용된다. Spring 코드나 설정을 바꿨다면 Spring 서버도 재시작한다. 서버는 실행 창에서 `Ctrl + C`로 중지한다.

## 9. 자주 발생하는 문제

| 증상 | 확인할 내용 |
| --- | --- |
| Python 서버에서 `No module named ...` 오류 | `ai-server` 폴더에서 `.venv`를 만들고 `requirements.txt`를 설치했는지 확인한다. |
| 대화 시작·전송 실패 | Python·Spring·MariaDB가 켜져 있는지, `OPENAI_API_KEY`가 **Python 서버를 실행한 창**에 설정됐는지, API 사용 권한과 사용량이 있는지 확인한다. |
| 지역이나 관광지를 불러오지 못함 | Python 서버를 실행한 창의 `TOUR_API_KEY`, 관광공사 서비스 활용 신청·승인 상태와 네트워크 연결을 확인한다. 일반 인증키(Decoding)를 사용한다. |
| `Address already in use` 또는 포트 충돌 | 같은 포트를 쓰는 기존 서버가 이미 실행 중인지 확인한다. 기존에 띄운 창이 있다면 필요에 따라 중지하고 다시 실행한다. |
| 저장된 대화를 불러올 수 없음 | Spring 서버가 재시작됐거나 비회원 세션이 만료됐을 수 있다. 메인에서 새 대화를 시작한다. |
| 조건을 확인했는데 장소가 없음 | 해당 지역의 관광지를 아직 가져오지 않았을 수 있다. **관광지 찾아보기**에서 지역을 선택해 가져오고 조건에 반영한다. |
| 화면만 켜지고 대화가 실패함 | Vite 화면 외에 Spring과 Python 서버가 각각 실행 중인지, Spring의 DB 연결이 정상인지 확인한다. |

오류를 공유할 때는 **API 키, DB 비밀번호, 전체 인증 URL을 지운 뒤** 상태 코드와 오류 문구만 공유한다.

## 10. 현재 구현 범위

- **동작:** 대화 저장, 여행 조건 수집·확인, 지역별 관광지 API 조회 및 조회 페이지 DB 저장, 저장된 관광지 후보 추천
- **아직 미구현:** 관광지 전체 자동 수집, 장소 상세 정보 수집, 벡터 검색·RAG, 날짜별 여행 일정 생성, 정식 코스 저장, 일정 수정, 회원 로그인 연계
- 별도 메뉴인 **조건검색**은 현재 화면 형태로만 구성되어 있고, 대화의 관광지 추천 기능과 연결되어 있지 않다.

코드 구조와 다음 작업은 `docs/AI완료작업.md`, Python 서버 상세 설정은 `ai-server/README.md`를 참고한다.
