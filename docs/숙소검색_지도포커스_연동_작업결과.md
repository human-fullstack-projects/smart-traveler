# 숙소 검색 지도 포커스 — course.destination 연동 작업 결과

2026-11-17. `#/stays` 숙소 검색 페이지의 카카오맵 포커스를 `course.destination`(내 코스 화면에 표시되는 지역 문자열) 기준으로 이동시키는 기능을 검토·구현·검증했다.

## 배경 조사

- `#/stays` 검색 페이지(`StaySearchPage.jsx`)는 지역 선택 `<select>`(부산/서울/제주 3개 고정)과 하드코딩된 `regionCenters` 좌표로만 카카오맵 중심을 잡고 있었다. `course.destination`(예: "부산광역시 동래구") 같은 임의의 지역 문자열을 지도에 전달할 방법이 없었다.
- `region` 테이블의 `center_latitude`/`center_longitude` 컬럼은 190행 전부 NULL이라 DB에서 바로 좌표를 구할 수 없었다.
- `course.destination`은 `region.full_name`과 문자열로 정확히 일치하며(`CourseRegionController`가 이미 이 매칭을 사용), `MyPageRepository`에서 저장된 코스의 `region` 필드도 실제로는 `course.destination` 컬럼 값을 그대로 담아 내려준다.
- `place`, `lodging` 테이블은 `region_id`별 실좌표를 보유하고 있어 대안 좌표 소스가 될 수 있었으나, 이번 작업 범위에서는 채택하지 않았다(아래 범위 참고).

## 범위 결정

사용자 확인을 거쳐 범위를 다음과 같이 최소화했다.

- 좌표 변환: 백엔드/DB 변경 없이 **프론트엔드에서 Kakao Geocoder**로 destination 문자열을 직접 지오코딩.
- 진입 경로: `#/my-courses` 화면의 코스 카드에 **실제 "숙소 찾기" 링크**를 추가해 destination을 `#/stays`로 전달.
- 숙소 목록/마커 데이터: 기존 **데모 데이터(`stayData.js`) 유지**. `/api/stays` 실연동은 하지 않음.

## 구현 내용

- `frontend/src/components/map/resolveKakaoPlace.js`
  - 기존에 파일 내부에서만 쓰던 `addressSearch(maps, address)`를 `export`로 전환해 재사용.
  - `resolveDestinationCenter(maps, destination)`을 추가. 주소 검색을 먼저 시도하고 실패하면 키워드 검색으로 재시도해 `{ latitude, longitude }` 또는 `null`을 반환한다.
- `frontend/src/pages/stays/search/StaySearchPage.jsx`
  - `#/stays?destination=...` 해시 쿼리를 읽는 `readDestinationQuery()`를 추가.
  - 마운트 시 `loadKakaoMaps()` + `resolveDestinationCenter()`로 destination 좌표를 구해 `destinationCenter` state에 저장.
  - destination 문자열에 "부산"/"서울"/"제주"가 포함되면 지역 select 초기값을 해당 지역으로 자동 선택(`matchDemoRegion`). 매칭되지 않으면 `'부산'` 기본값을 유지하고 "데모 숙소 데이터가 없어 목록은 기본 지역 결과를 표시합니다" 안내 문구를 노출.
  - 지도 중심 계산을 `selected?.demoCoordinate || destinationCenter || regionCenters[region]` 순서로 변경. 사용자가 숙소를 직접 선택하면 그 숙소 좌표가 여전히 우선한다.
- `frontend/src/pages/mypage/pages/MyCourses.jsx`
  - 비회원 추천 코스 카드와 저장된 코스 카드 각각에 "숙소 찾기" 링크를 추가. `href="#/stays?destination=" + encodeURIComponent(course.destination ?? course.region ?? '')`로 필드명 차이를 방어적으로 처리.

백엔드·DB 스키마 변경은 없다.

### 확인하지 못한 부분

검증에 사용한 샌드박스 환경은 `dapi.kakao.com`(카카오맵 SDK) 외부 요청을 `ERR_BLOCKED_BY_ORB`로 차단한다. 이 때문에 지도가 destination 좌표로 실제로 패닝되는 모습 자체는 이 환경에서 육안 확인하지 못했다. SDK 로드 실패 시 기존 `MapFallback`("지도를 불러오지 못했어요")으로 깨지지 않고 정상 폴백되는 것은 확인했다. 실제 서비스 환경(카카오 키가 도메인 등록된 브라우저)에서 한 번 더 육안 확인을 권장한다.
