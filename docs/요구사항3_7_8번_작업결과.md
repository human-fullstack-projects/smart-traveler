# 요구사항3 — 7·8번 작업 결과

2026-11-17. 작업 전 분석을 설명한 뒤 사용자의 “진행해라” 지시에 따라 구현했다.

## 구현한 기능

- 비회원에게 추천을 표시한 뒤 1위 코스 정보를 Spring `HttpSession`에 보관한다. 보관 정보에는 원본 코스·추천 메시지 ID와 코스명, 지역, 날짜·여행 조건, 일차별 장소 ID·이름·순서가 포함된다.
- 여러 추천에서는 최신 추천의 1위 코스 1개를 유지한다. 이전 추천의 보관 요청이 늦게 도착해도 최신 추천을 덮어쓰지 않는다.
- 새로고침 후에도 보관 상태를 서버에서 조회하며 ‘내 코스’ 목록에 비회원 추천을 표시한다. 로그인·회원가입 화면에서도 보관 개수를 안내한다.
- 일반 로그인·소셜 로그인·로그인된 상태로 앱 재진입 시 인증 확인 후 같은 이전 API를 호출한다. 가입만 하고 로그인하지 않은 시점에는 회원 코스를 만들지 않는다.
- 서버 인증에서 확인한 활성 회원 ID로 `course`, `course_day`를 생성한다. 원본 코스의 소유자는 바꾸지 않는다. 날짜·방문지는 1~6번의 검증된 추천 스냅샷을 재사용한다.
- 같은 추천의 반복·동시 이전 요청은 저장된 코스 ID를 반환한다. 여러 탭에서 요청해도 코스는 1개만 생성된다.
- DB 커밋 성공 이후에만 세션의 대기 정보를 제거한다. INSERT나 최종 커밋이 실패하면 보관 정보를 유지하고 재시도할 수 있다.
- 첫 이전 시도 계정에 연결하여, 실패 뒤 다른 계정으로 바뀌면 임의 이전을 차단한다. 이전 계정의 채팅 기록 접근 권한은 복구하지 않는다.
- 로그인 화면 이동 전에 진행 중인 비회원 보관 요청을 기다린다. 코스 이전에 실패하면 로그인 상태를 유지하고 재시도 안내를 표시한다.
- 기존 ‘조건과 고정 일정만 임시 보관’ 버튼을 채팅에서 제거해 실제 RAG 코스를 별도 초안으로 중복 저장하지 않게 했다. 기존 수동 초안 저장 기능 자체는 유지한다.

## API

| API | 역할 |
| --- | --- |
| `POST /api/chat/sessions/{id}/recommendations/{messageId}/guest` | 소유권을 확인한 비회원 추천을 세션에 보관 |
| `GET /api/chat/guest-course` | 세션의 보관 코스 요약 조회 |
| `POST /api/chat/guest-course/claim` | 인증된 현재 회원에게 한 번만 이전 |

변경 요청의 CSRF 검증과 채팅 소유권 확인을 유지한다. 클라이언트의 회원 ID나 임의 코스 내용을 받아 저장하지 않는다. 1~6번에서 추가한 nullable `recommendation_json` 컬럼 외에 추가 스키마 변경은 없다.

## 보관 기간

새로고침과 사이트 내부 이동으로 보관 정보가 사라지지 않는다. 로그아웃·서버 세션 만료·서버 세션 소실 시에는 사라진다. 브라우저 종료 시 쿠키 복원 여부와 서버 세션 설정에 따라 유지 여부가 달라지므로 영구 보관으로 안내하지 않는다. 회원 DB 저장이 성공하면 이후에는 회원 코스로 유지된다.

## 검증

- Python 전체 52개 테스트 통과.
- DB 감사 테스트를 활성화한 Java 전체 111개 테스트 통과, 실패·건너뜀 0.
- 실제 회원가입·일반 로그인으로 세션 ID가 바뀌어도 대기 정보가 유지되고, 정확한 회원에게 1개만 저장됨을 확인했다.
- 소셜 로그인에서 사용하는 `SocialSessionLogin`의 세션 교체 후 두 요청을 동시에 실행해 동일한 코스 ID가 반환되고 DB에 1개만 생성됨을 확인했다. 외부 소셜 제공자의 인증 화면은 호출하지 않았다.
- 일차 저장 중 중복 키 오류를 발생시켜 생성 중인 코스가 롤백되고, 대기 정보가 유지되며, 다른 계정은 차단되고 원래 계정의 재시도는 성공함을 확인했다.
- 단위 테스트로 최종 커밋 실패 시에도 세션 정보를 지우지 않는 동작을 검증했다.
- 비회원 새 세션에서는 기존 보관 정보가 조회되지 않으며 로그아웃 시 세션이 무효화됨을 확인했다.
- 프론트 프로덕션 빌드 통과. React 렌더링으로 비회원 코스 목록·로그인 링크·긴 코스 출력을 확인하고, API 요청 모의 테스트로 로그인 요청보다 비회원 보관 완료가 먼저 수행됨을 확인했다.
- DB 통합 테스트는 실제 커밋을 사용한 뒤 생성한 테스트 계정·동의·채팅·코스를 정리했다.

실제 브라우저 클릭부터 실제 OpenAI 추천까지 이어지는 전체 수동 E2E는 수행하지 않았다. 추천 모델 경로는 기존 테스트를 유지하며 이번 검증은 보관·인증·DB 이전과 프론트 연결에 집중했다.

## 재현

`smarttraveler`에서 테스트 DB를 대상으로 실행한다.

```powershell
$env:RAG_DB_AUDIT='true'
.\gradlew.bat test --console=plain
```

`frontend`에서 실행한다.

```powershell
npm run build
node src/pages/ai-chat/tests/verify-rag-display.mjs
```

실제 코스 추천 경로는 기존과 같이 Spring 실행 환경에 `COURSE_RAG_ENABLED=true`를 설정해야 한다.
