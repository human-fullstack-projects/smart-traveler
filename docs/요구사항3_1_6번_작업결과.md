# 요구사항3 — 1~6번 작업 결과

2026-11-17. 저장 기준은 사용자가 선택한 **1위 코스 1개 자동 저장**이다.

## 구현 기능

1. `/chat` 시작 화면과 대화 화면에 ‘관광지 찾아보기’를 추가했다.
2. `GET /api/chat/course-regions`는 `region.full_name`과 `course.destination`이 일치하는 지원 지역을 조회한다. 폐지 지역은 제외한다.
3. 지역 선택 시 서버가 ID를 확인하고 지역 ID·이름을 대화 조건에 저장한다. 확인 상태는 해제하며, 선택 내용을 사용자 메시지로 표시한다.
4. 지정된 다섯 줄의 첫 질문을 시작 화면에 표시하고 새 대화의 첫 안내 메시지로 기록한다.
5. 한 번의 답변에서 여러 여행 조건을 추출하는 기존 RAG 흐름을 유지하고, 부족한 값은 추가 질문한다. 조건 변경 후에는 재확인한다.
6. Python이 실제 1위 ID를 별도 필드로 반환한다. Spring이 후보 ID를 검증하고 회원 추천의 일정 스냅샷을 기록한다. 화면 표시 후 자동 저장 API를 호출하여 회원 소유 `course`, `course_day`를 생성한다.

## 저장 기준

- 인증된 활성 회원 ID를 서버에서 확인한다. 브라우저에서 회원 ID나 코스 내용을 받아 저장하지 않는다.
- 추천 메시지마다 1위 코스 1개를 저장한다. 같은 메시지의 저장 요청이 반복되면 기존 저장 코스 ID를 반환한다.
- 다른 추천 메시지에서 다시 추천받는 것은 별도의 추천 결과로 취급한다.
- 원본 추천 코스의 소유권은 변경하지 않는다.
- 방문 시간이 없는 시드에는 임의의 시간을 만들지 않는다. 장소 ID·이름·방문 순서는 `condition_meta.itinerary`에 저장하고 마이페이지 상세에서 표시한다.
- 저장에 실패해도 이미 표시한 추천 내용은 유지하고 다시 저장할 수 있다.
- 코스가 없는 안내·조건 확인·관광지 추천 응답에서는 코스 저장을 실행하지 않는다.

## 스키마와 실행

- `chat_messages.recommendation_json` nullable JSON 컬럼을 추가했다. 프로젝트의 Hibernate `ddl-auto=update`를 사용하면 시작 시 반영된다.
- 스키마 자동 갱신을 사용하지 않는 환경에서는 `data/rag_recommendation_storage.sql`을 적용해야 한다.
- 코스 RAG는 기존과 같이 Spring 실행 환경의 `COURSE_RAG_ENABLED=true`로 활성화한다. `false`인 관광지 추천 경로도 유지한다.

## 검증

- Python 52개 테스트 통과.
- DB 감사 테스트를 활성화한 Java 전체 105개 테스트 통과. 지역 목록과 목적지 일치, 선택 지역 적용, 첫 안내 문구, 회원 저장 및 동일 요청의 중복 방지, 원본 소유권 유지, 저장한 날짜와 장소 상세 조회, 타인·비회원 저장 접근 차단을 포함한다.
- 프론트 프로덕션 빌드 통과.
- React 렌더링에서 첫 질문·지역 선택 칸과 4일 코스 3개, 10,579자 표시 확인.
- DB 통합 테스트에서 생성한 코스·채팅은 테스트 트랜잭션 종료 시 롤백했다. nullable 컬럼 추가는 스키마 변경으로 유지된다.
- 브라우저의 실제 클릭부터 실제 OpenAI 응답·회원 저장까지 이어지는 수동 E2E는 이번 작업에서 수행하지 않았다. Python 응답 계약·Spring 보안 체인·실제 DB 저장·React 렌더링을 각각 검증했다.

이 문서의 1~6번 완료 시점에는 7·8번의 별도 진행 지시를 기다렸다. 이후 설명과 사용자 승인을 거쳐 7·8번도 구현했으며, 최종 결과는 `요구사항3_7_8번_작업결과.md`에 기록했다.
