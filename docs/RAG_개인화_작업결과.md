# RAG 개인화 구현 및 검증 결과

2026-11-17. `Smart_Traveler_실제_소스_기반_RAG_작업_가이드.md`의 Phase 1~5 순서로 구현하고 검증했다. 원본 가이드의 점검 시점 기록은 변경하지 않았다.

## Phase 1 — 기준 경로와 실제 데이터

- 기존 Python 테스트 25개, Java 테스트 94개 통과를 확인했다.
- 로컬 MariaDB의 지정 배치 1,000건을 조회했다. 지역·일수별 214개 묶음에서 활성·완료·미삭제 여부, 1~4일 기간, 일차 및 방문 순서, 장소 ID와 활성 상태를 확인했으며 탈락 코스는 0건이었다.
- 반복 조회용 읽기 전용 SQL은 `data/rag_candidate_audit.sql`에 추가했다.
- 현재 Java의 확인 문구 접두사는 Python 재확인 문구도 포함하므로 가이드에서 우려한 문제가 그대로 재현되지는 않았다. 문구 변경에 따른 누락을 예방하도록 Java는 필수 조건이 갖춰지면 후보를 공급하고, 추천 여부는 Python이 판별하도록 변경했다. Python은 조건이 변경되면 여전히 재확인을 요구한다.
- 실제 `StoredCourseCandidates`를 통한 부산 후보 수는 1일 19개, 2일 21개, 3일 10개, 4일 5개였다.

## Phase 2 — 인증과 저장 취향

- `ChatPersonalization`에서 매 요청의 서버 인증을 읽고 `MyPageService.owner`로 활성·미삭제 회원을 확인한다.
- 생성·후속 메시지 양쪽에서 기존 `PreferenceRepository`를 조회한다. `saved=false`인 DTO의 기본 `normal`은 개인화로 사용하지 않는다. 비회원은 취향 조회를 생략한다.
- 저장된 pace와 긍정 선택한 설문의 `장소:…`, `선호지역:…`만 전달한다. `둘 다`는 환경 가중치를 사용하지 않는다. 회원 ID·기상 시간·일반 관심 태그·회피 설문 태그는 AI 요청에 넣지 않는다.
- 선택적 `savedPreferences`는 대화 조건과 별도로 전달하고 `chat_session_conditions`에 저장하지 않는다.
- 서버는 인증 주체가 달라지면 채팅용 랜덤 접근 토큰을 교체한다. 기존 채팅의 조회·메시지 전송·조건 저장은 이전 토큰으로 접근할 수 없다. 이전 버전의 주체 구분 없는 세션도 첫 접근 때 새 토큰을 받는다.
- 프론트는 인증 확인 후 대화를 복원하고, 주체 변경 시 상태를 비우며 이전 요청의 늦은 응답을 폐기한다. 로그인·로그아웃을 다른 탭에도 알리고 채팅 요청의 CSRF 토큰을 갱신한다.

## Phase 3 — 정규화와 리랭킹

- 시드 배치 제한과 지역·일수 조회 범위를 유지했다. 풍경 메타데이터는 JSON 문자열 대신 정규화된 배열로 전달한다.
- 공통 풍경 값은 `city`, `countryside`, `water`, `island`, `forest`, `sea`다.
- 인식 가능한 대화 취향이 같은 항목의 저장 취향보다 우선한다. 구조화하지 못한 일반 취향은 기존 임베딩 질의에 남긴다.
- 명시적 제외를 먼저 적용한다. 후보의 미분류 정보로 제외 충족을 확인할 수 없으면 탈락시키며, 인식할 수 없는 제외 조건은 추가 설명을 요청한다.
- 임베딩 관련도 상위 20개에 가이드의 `0.50R + 0.20T + 0.15I + 0.15L`을 적용한다. 미설정 가중치는 제거하고 재정규화한다. 후보 미분류는 0.5이며 일치 근거에는 포함하지 않는다.
- 동점은 관련도와 코스 ID 순서로 정렬한다. 정형 취향이 없으면 1개, 있으면 최대 3개를 반환한다. 초기 가중치는 유지했으며 품질 평가 데이터에 따른 추가 조정은 하지 않았다.

## Phase 4 — 출력과 실패 처리

- 코스 ID·제목·방문지·방문 순서는 서버 후보에서 사용하고 요청 출발일에 맞춰 날짜를 표시한다.
- LLM은 실제 일치 태그와 선택 코스 정보만 받아 이유를 작성한다. 운영시간·이동시간·숙소 및 예약 가능 여부를 추측하지 않도록 지시한다.
- 이유 생성이 실패하면 일치 태그 또는 지역·일수에 근거한 기본 설명으로 선정 코스를 표시한다.
- Java 응답 검증, Python 응답 및 후속 `previousQuestion` 한도를 함께 20,000자로 조정했다. 프론트는 기존 문자열 표시를 유지한다. 실제 React 렌더링에서 4일 코스 3개, 10,579자가 누락 없이 표시됐다.

## 재현

Python 테스트는 `ai-server`에서 실행한다.

```powershell
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
```

Java 테스트는 시드가 적재된 테스트 DB에 연결된 `smarttraveler`에서 실행한다. `RAG_DB_AUDIT`를 지정하지 않으면 실제 DB를 요구하는 두 감사 테스트는 건너뛴다.

```powershell
$env:RAG_DB_AUDIT='true'
.\gradlew.bat test --console=plain
```

프론트 검증은 `frontend`에서 실행한다.

```powershell
npm run build
node src/pages/ai-chat/tests/verify-rag-display.mjs
node src/pages/mypage/tests/verify.mjs
```

실제 OpenAI 재검증은 DB 감사 테스트 이후 `ai-server`에서 실행한다. 기존 환경변수 또는 로컬 `.env`의 연결 설정을 사용하며 결과에 키·회원 정보를 기록하지 않는다.

```powershell
.\.venv\Scripts\python.exe scripts/smoke_course_rag.py --live
```

로컬 감사 산출물은 Git에서 제외되는 `smarttraveler/build/rag-audit-candidates.json`, `smarttraveler/build/rag-live-smoke.json`이다.

실제 채팅에 적용하려면 **Spring 실행 환경에 `COURSE_RAG_ENABLED=true`를 설정**한다. 기본값 `false`는 유지했다.
