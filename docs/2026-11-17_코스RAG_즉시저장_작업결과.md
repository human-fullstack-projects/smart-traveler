## 1. 핵심 변경: "코스 저장" 버튼 제거, 추천 출력 즉시 저장

기존에는 사용자가 추천 코스를 받은 뒤 별도 저장 요청을 보내야 `course`/`course_day`에 반영됐다. 이번 작업으로 **추천 메시지가 만들어지는 순간, 로그인 회원이면 같은 트랜잭션 안에서 바로 영구 저장**되도록 변경했다.

- `smarttraveler/.../chat/RecommendedCourseService.java`
  - `record(sessionId, messageId, sourceId)`가 스냅샷 생성 후 `chat_sessions.member_id`를 조회해, 로그인 세션이면 `persist()`를 호출해 즉시 `course`/`course_day`에 저장하고 `savedCourseId`를 스냅샷에 채움.
  - 기존 `save()`/`persist()` 로직은 공통화해 재사용 — 명시적 `/save` 호출(재시도, 비회원→회원 전환 `claim()`)도 계속 지원하며 중복 저장은 방지.
- `frontend/src/pages/ai-chat/hooks/useAiChat.js`
  - 회원 추천은 서버 응답에 이미 `savedCourseId`가 포함되므로 별도 `/save` POST 없이 즉시 "저장됨" 상태 표시. 서버가 즉시 저장 못한 예외 상황을 위한 재시도 경로는 fallback으로 유지.
  - 비회원(게스트) 플로우(세션 보관 → 로그인 시 `claim`)는 기존과 동일.

## 3. Spring 쪽 코스 RAG 연동

- `COURSE_RAG_ENABLED` 플래그(기본값 `false`)로 코스 RAG 경로를 Python에 전달할지 결정 (`ConditionDialogueService.java`).
  - `true`일 때만 `StoredCourseCandidates.find()`로 코스 후보를 조회해 `courseCandidates`로 Python에 전달.
  - `false`(기본)면 기존 장소(관광지) 추천 경로만 동작 — 아직 전면 검증 전인 기능이라 옵트인으로 운영.
- `ChatPersonalization.java` 신규: 인증 컨텍스트에서 로그인 회원의 저장 취향을 조회해 AI 요청에 전달 (클라이언트가 보낸 회원 ID는 신뢰하지 않음).
- `CourseRegionController.java` 신규: `/chat`의 "관광지 찾아보기"에서 코스 목적지와 일치하는 DB 지역 조회.
- `GuestRecommendedCourseService.java` / `GuestRecommendedCourseController.java` 신규: 비회원이 추천을 화면에서 받은 뒤 서버 세션에 1건 보관, 로그인 시 `claim()`으로 소유권 이전(member_id 갱신 + `course` 저장), 동시 요청·커밋 실패 시에도 중복 저장되지 않도록 처리.
- `ChatController.java`, `ConditionQuestions.java`, `PythonAiClient.java`, `StoredCourseCandidates.java`, `ChatMessage.java`(`recommendation_json` 컬럼), `MyPageRepository.java` 등 연동 수정.

## 6. main 머지 시 충돌 해결

`frontend/src/contexts/AuthContext.jsx`에서 1건 충돌:

- `origin/main` 쪽: 탭 복귀·페이지 이동·API 401 응답 시 로그인 상태를 재확인하는 `useEffect` (다른 팀원 작업, PR #39).
